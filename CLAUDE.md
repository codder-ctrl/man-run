# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Man Run: a Fun Run–style side-scrolling race in the browser. Four chibi animals (the player and three bots) auto-run to a finish flag; the player only jumps and fires items from "?" boxes. The user wants it as close to Fun Run as possible and plays it with friends. Online play uses 4-letter room codes over WebRTC (browsers can't link phones over Bluetooth; the user picked room codes). `index.html`, `styles.css`, native ES modules in `js/`. No build step, no npm dependencies; the only external resources are the Lilita One and Fredoka fonts, and PeerJS from jsDelivr (loaded only when someone opens online play). UI text is Turkish. Landscape, phone first.

## Workflow with the user

The user doesn't read code. Big steps go: plan → build → present with a 1–10 rating request plus Claude's own scores (akıcılık, grafik, efektler, ses, oynanış) → adjust. Explain changes in Turkish, in player terms. Push only when the user says "yükle". Keep `DEVAM-OZETI.md` up to date for the next session.

## README

`README.md` mirrors Slasher Hero's: English text with Turkish game terms, and a big "Play" link to the live site at the top (the user opens the game from the repo page). The repo's homepage field also points at the live site. Update the "How it plays" section when controls or mechanics change.

## Releases

Bump `VERSION` in `js/config.js` and `package.json` together (`tests/pwa.test.js` checks). New feature = minor, fix = patch. There is no changelog screen yet.

## Deploying

Repo: `codder-ctrl/man-run` (public). GitHub Pages serves the repo root of `main` at https://codder-ctrl.github.io/man-run/, so every push to `main` is a release; run `npm test` first and push only when the user says "yükle". `.nojekyll` keeps Pages from running Jekyll. The site lives under `/man-run/`, so keep every path in the page, manifest and `sw.js` relative.

## Running and testing

- Serve over HTTP: the `man-run` entry in the parent `.claude/launch.json` (port 8004), or `python -m http.server 8004`.
- `npm test` (`node --test`): `tests/race.test.js` races four bots on several seeds headless and fails if anyone can't finish; run it after any change to track generation, physics or the AI. `tests/pwa.test.js` checks the service worker shell and relative paths.
- `tools/pose-lab.html?cell=160&ids=fox,panda` shows every animal in every pose.
- `tests/net.test.js` wires a host race and a guest race together in memory with 50 ms of lag and checks they stay in step to the end; run it after touching `game.js` roles or `netsync.js`.
- Online in the browser pane: open the game in two tabs (`tabs_create`), call `manrun.pump()` in both (drives the loop from a MessageChannel; background tabs otherwise freeze), host in one, join with the code in the other, and drive the buttons with `.click()`. Hard-refresh modules with `await fetch('/js/x.js', {cache: 'reload'})` before `location.reload()`: the local server lets the browser cache them. The real PeerJS server is used, so this needs internet.
- `?auto=1` makes the player a bot too. On localhost `window.manrun` has `{ race, mode, online, startRace, renderer, input, advance(seconds), pump(), stopPump(), useItem(id) }`. The browser pane throttles animation frames when hidden, so drive tests with `manrun.advance(s)` (steps and draws synchronously, consumes queued input) and take two screenshots (the first can be stale). Synthetic `PointerEvent`s work on `#touch-jump`, `#btn-jump`, `#btn-item`. For an auto player, `useItem` is ignored (the bot brain drives it); call `race.useItem(race.player)` instead.
- Icons: `npm run icons` (`node tools/icon-server.js`), then open http://localhost:8091/tools/icons.html; it writes `icons/*.png` and exits.
- Key art: `npm run splash` (or the `man-run-art` entry in the parent `.claude/launch.json`), then open http://localhost:8091/tools/splash.html; it writes `img/splash.webp` (loading screen, 2560×1280) and `img/menu-bg.webp` (menu backdrop, no logo or runners, 1920×960) and exits. The picture is painted by `tools/splash.js` with the game's own characters and props; it can use effects a frame can't (blur layers, tens of thousands of grass blades, bloom). Keep the logo and runners inside the middle ~2160×1080 (phones and 16:9 screens crop the 2:1 image with `object-fit: cover`) and the bottom middle calm for the loading bar.

## Architecture

`config`, `themes` → `track` → `physics` → `ai` → `game` (rules, no DOM) → `netsync`; `net` → `online`; `paint` → `animals`, `scenery`, `fx` → `render`; `sound`; everything → `main`.

- **World units**: y grows downward, a runner is ~60 tall, the camera shows `VIEW_H` (430) units vertically (a bit less on short screens). Physics runs at a fixed 1/120 s step (`STEP`).
- **`track.js`**: `buildTrack(seed, { theme })` chains segments (flat, rolling bumps, hill up/down, valley, step up/down, stairs, wall, wall+spikes, upper ledge route, mud, speed pad, pad before a wall, big step down, low roof, box row). **No pits** since v0.8 (the user asked for no falling gaps): ground strips touch end to end; `tests/race.test.js` checks it. `respawn`/`fall` still exist as a safety net with difficulty rising along the track; a box row is forced every ~950 units. Ground strips (`kind: 'ground'`) carry a height profile `ys` every `DX` (8) units; `surfaceAt`/`slopeAt` read it. Slopes are capped at 0.5 by the segment builder. `undulate` then lays a gentle roll over everything except flat zones (spikes, mud, pads, walls, under ledges, 50 units at each strip end, start/finish), so heights there stay as designed. `T.back` is the decorative back-wall profile (a raised, smoothed copy of the ground, continuous over pits). Other output: `block` walls, `plat` one-way ledges, `spikes`, `mud`, `pads`, `boxes`, `respawns`, `deco` (theme's `decoSet`), `finishX`. Spatial buckets for `solidsNear`.
- **Sliding** (`physics.js`): EĞİL is a tap like jump (the user asked for it). One press slides for `PHYS.slideTime` (0.7 s, box `PHYS.duckH` 28, feet-first pose) and the runner stands up by itself; pressed in the air it dives (`fastFall`) and slides on landing. `roofAbove` keeps a runner ducked while a block or roof is over its head; jumping needs headroom.
- **Speed cost** (user's rule): in the air after a jump (`r.airJump`) and while sliding, top speed is `PHYS.moveSlow` (0.8) of normal, dropping at `airDecel` in the air. The widest pits were narrowed to 145 so jumps still clear them.
- **Wall cling** (`physics.js`; the user asked for it with the v0.8 ratings, replacing v0.5's auto-climb): a runner in the air that touches any upright wall (`res.blocked && res.wall`: blocks, steps, strip ends; not while ducking) sticks to it (`r.climb`). Clinging, it slides down at most `PHYS.wallSlide` (70 units/s); each jump press kicks it up a full jump (`-jumpV`) and it grips again as the kick slows, so jumping again and again walks up the wall; once the body clears the top it hops over (`res.topped`). Reaching the foot ends the cling; a burst into a wall clings too. Roofs can't be climbed. `moveBody` reports the wall it hit (`res.wall`). Bots still treat walls as danger and jump; on a wall they press jump again once the kick has slowed (`vy >= -100`). `animals.js` draws a cling pose (paws up, legs dangling) while sliding and the climb animation while rising. `roof` solids (track segment `duck`) hang 32 units above flat ground and are 130 tall, so they can only be slid under; bots check `simulate(..., duck=true)` when a wall shows up ahead. The roof is drawn as a rock overhang with hazy pillars behind it and a warning sign before it.
- **Aiming** (user asked for Brawl Stars–style aiming, then for all of it to be full circle and for items to wait for the release): one controller in main.js (`aim`, `aimStart(kind)`, `aimMove`, `aimEnd`) serves the 🐾 and item buttons. Nothing is used until the button is let go. The paw, the saw and the trap (`AIMED_ITEMS`) aim all the way round (`normAngle`; 0 = forward, π/2 = up, ±π = back); a tap is the plain use (paw forward, saw rolling forward, trap dropped behind: `itemAngle = null`). Lightning, anvil, shield and speed just wait for the release; the runner holds the item up (`aim = π/2`, `aimKind` = the item) and only the player sees a pulsing ring and "BIRAK!". Keyboard: hold Q or E, turn with ↑/↓. `r.aimKind` ('paw' or an item id) travels online as `ak` / snapshot index 25; a guest's item use sends `{ t: 'use', a }`. Thrown items (`game.js`): `makeSaw` flies along the aim under gravity and rolls on in its direction once it lands; saws are big (`SAW_R` 30, the user asked for 2.5×) and bounce back off upright walls (`stepSaw`: a blocked saw flips `dir` and hops, `sawBounce` event); a saw mows through runners (the user asked for it): it knocks down each runner once (`s.hits`), never breaks on a hit, and is gone when `SAW_LIFE` (3.2 s) runs out, shrinking and fading in its last 0.4 s (`life` travels in snapshots); `makeTrap` with an angle is lobbed (`TRAP_THROW`) and is harmless until it lands (`stepTrap`); traps are `TRAP_SCALE` (1.5×) bigger and never catch their owner. `predictItemPath` gives the private preview. Bots roll saws back at a chaser when nobody is ahead.
- **Aimed blue paw details:** holding 🐾 and dragging sets `aim` (angle from the press point to the finger). While aiming, `r.aim` is set for the local runner: everyone sees the front arm point there with a glowing orb (`poseFor` wraps `basePose`; online it travels as `am` in reports and index 24 in snapshots), and only the aiming phone draws `drawAimGuide` (range arc, `predictBurst` dotted path, pulsing arrow). Releasing calls `usePaw(race, r, angle)` → `startBurst`: `PAW_BURST` (0.22 s) at ability speed × `PAW_BURST_MUL` (1.2) along the aim with gravity off (on the ground a downward aim becomes flat forward or backward), then half the rise carries on and the usual dash boost runs for the rest of `time`. A wall ends the burst and the runner clings to it, so does a ceiling or landing from a dive. Bots aim for 0.3–0.65 s (visible) at the angle in `PAW_ANGLES` that gets furthest without a pit or spikes (`simulate(..., burst)`). `tests/abilities.test.js` checks the burst against a jump and running.
- **Blue paw** (`config.ABILITIES`, `game.usePaw`): each animal's own dash (name, speed, time; the extra distance is about the same for all). It charges over `PAW_CHARGE` (15) seconds, only while not dashing. Dashing ignores mud, a hit cancels it. It's movement, so it belongs to the runner's own phone: a guest dashes locally and reports `ds`; `paw` events for remote runners are inferred from `dash` going above 0. Drawn as a blue glow, blue afterimages and paw prints.
- **`physics.js`**: `moveBody` (AABB vs solids; inside a ground strip any slope is walkable: rising slopes lift the feet, going downhill snaps to the ground; only strip ends are walls, step-up ≤10; one-way ledges; ceilings only for blocks), `stepRunner` (accel to top speed, uphill −20%/downhill +20%, coyote time, jump buffer, variable jump with a minimum hold so quick taps still clear walls), `simulate` (bots' what-if runs).
- **`themes.js`**: `THEMES` (forest, snow, desert): sky, layers, back wall, grass/snow/sand cap, dirt cobbles, blocks (ice in snow), foreground colors, weather, decoration set, tree type, music mood. A new map is a new entry.
- **`ai.js`**: every 1/30 s a bot simulates "keep running" 0.4 s ahead; on danger (pit, wall, spikes) it simulates "jump now" and jumps with its skill's reaction chance (always when urgent). Occasional hesitation (`slip`) makes them fall sometimes. Mild rubber-banding against the player via `speedMul`. Item rules per item after a short delay.
- **Online model** (`game.js` roles, `netsync.js`): `race.role` is `solo`, `host` or `guest`; each runner's `ctrl` is `local`, `bot` or `remote`. The host runs the whole race (bots, items, hits, boxes, places, finish, results). Each guest moves **only its own runner** locally, so jumping has no lag, and reports it 30 times a second (`st`); item presses go to the host (`use`). The host sends snapshots 20 times a second (`s`: every runner as a compact array, active boxes, saws, traps, anvils) plus the events since the last one (hits, uses, finishes, `done` with results). The guest applies host-owned fields to its own runner (shield, boost, item, place, finish; a hit event calls `applyHit` on its body) and draws everyone else interpolated 100 ms behind. Movement effects (jump, land, fall, respawn) of remote runners are inferred locally from state changes, never sent. A friend who disconnects or goes silent for 5 s becomes a bot (`makeBot`); a guest that hears nothing for 6 s leaves. Hit-stop and pausing are off online.
- **`net.js`**: PeerJS wrapper. The host's peer id is `manrun-v1-` + a 4-letter code (no I/O/Q/W/X); guests connect with a reliable JSON data channel. Turkish error messages.
- **`online.js`**: lobby. The host keeps the player list (unique animals, names up to 12 characters, max 4), the map (`Karışık` is settled on the host so every phone builds the same track) and the bots switch; `start()` broadcasts `{ seed, theme, roster }`. Joining is refused on a version mismatch, a running race or a full room. Rematch = `start()` again; "Lobiye Dön" = `toLobby()`.
- **Boxes are per runner** (user's rule): one box per spot (`boxRow` makes a single box, one about every 800 units); `b.taken[runnerId]` holds that runner's respawn timer, so taking a box hides it only for you and everyone can take the same box. The renderer shows boxes as the local player sees them and only plays box effects for the local player. Online, a guest marks its own boxes locally (`pickupBoxes(..., visualOnly)`) and ignores the host's `box` events for itself; the host rolls the item.
- **Traps are per runner too** (user's rule, v0.9): `t.caught[runnerId]` records when each runner was caught, so a trap catches every runner once and stays for the rest. Snapshots send traps as `[id, x, y, caughtMask, owner]` (bit = runner index). The renderer hides a trap from a viewer 1.6 s after it caught them (fading); traps set by someone else get a thick red rim and red glow, your own a thin one.
- **`game.js`**: race state, countdown, items (`ITEMS` weights by place: leaders get shields/traps, the last get lightning/anvil), hits/stuns, saws (bounce off walls), traps, anvils (warning, then drop on the leader), falls/respawns, places, finish. Emits events (`jump`, `box`, `use`, `hit`, `lightning`, `finish`, `done`…) drained by `main.js` into `render.onEvent` and sounds.
- **`animals.js`**: `poseFor(runner, t)` → pose (run cycle by distance, jump, fall, dazed, zapped, trapped, cheer); `drawAnimal` draws in the house style (stroked limbs, big head, scarf in the accent color). A lightning hit flickers the body to a dark x-ray silhouette with white bones and a skull (Fun Run's look). Animal look data lives in `ANIMALS` (config); a new animal is a config entry (`ears`, `tail`, colors, `snout`, `patches`).
- **`scenery.js`**: the depth layers. Backdrop: sky+sun+rays pre-rendered once per screen size, then clouds, far mountains/mesas (blurred), hills, treeline as cropped tiling canvases with parallax. Terrain: `createTerrain` paints the static track into 512-unit chunk canvases (cached at the base scale, one chunk warmed ahead per frame, only the visible part blitted). Since v0.8 the world is a meadow seen a little from above (the user asked: no earth cross-section, grass down to the bottom of the screen coming toward the viewer, a yellow-white footpath to run on): `drawBackMeadow` (field rising to the hill line `T.back`, rows getting hazier toward the top), trees and static deco on the far edge of the path (`d.y` = surface − 8), `drawMeadow` (near field in `FRONT_ROWS` following the path's curve, each row the grass tile at a bigger scale with a ragged grass edge over the row behind; haze far, shade near baked into the tile with `grassTile(th, kind, tint)` so a row is one pattern fill), `drawPath` (band from surface − 9 to + 18, `pathTile` pebbles, ruts, grass or snow spilling over both edges; feet stand at the surface), `drawSteps` (stone retaining wall where the path steps up or down), `drawBoardwalk` (ledges are wooden decks on posts standing on the path's far edge), stone/ice blocks, roofs, spikes. Colors: `theme.path`, `theme.meadow`, `theme.hill`. Never draw texture details one by one: a chunk with hundreds of paths took 100–1300 ms to rasterize and froze the game; use the cached tiles as patterns. Live: mud, pads, red "?" boxes, swaying deco, finish arch. `createForeground`: blurred plant sprites at parallax 1.4 along the bottom. `createWeather`: leaves, snow or sand streaks in screen space.
- **`fx.js`**: particles (soft and outlined dust puffs, shards, additive sparks and twinkles, stars, comic POW bursts, confetti, fireworks, smoke, speed lines), branching lightning bolts, shockwave rings, floating text. Glowing things draw in an additive pass. `drawItemIcon` draws Fun Run–style colored round badges.
- **`render.js`**: camera (x locked to the player at 30% across with a lead when boosted, y on a spring, slight zoom-out when boosted, zoom punch on hits), shake/flash, all layers in order, runners leaning into slopes, boost afterimages, shield bubble, x-ray glow, name tags, anvil warning, pre-rendered vignette. Adaptive quality: phones start at step 1. If frames stay slower than 45 fps for 1.5 s it steps the canvas DPR down (1.75 → 1.4 → 1.15 → 1) and turns off the vignette, then weather and foreground. A step rebuilds every cached layer (a hitch), so mid-race it waits for the next race; only the countdown applies it at once. Debug: `globalThis.__prof = {}` collects per-layer JS time, `globalThis.__skip = { backdrop, terrain, weather, fore }` skips layers.
- **`sound.js`**: soft Web Audio synth effects (sine/triangle, filtered noise, bells) through a low-pass, a generated room reverb and a compressor; a mellow 8-bar loop (soft keys, round bass, light drums, pentatonic lead) whose key, tempo and lead come from the theme's `music` mood. Starts on the first tap.
- **Loading screen** (`main.js`, user's request): the page opens on `#splash` (`mode = 'splash'`): the key art `img/splash.webp` with a striped loading bar and the chosen animal's head hopping along it, plus a random tip. `boot()` waits for the art, the fonts and the menu backdrop (each with a timeout); the bar eases on real time and takes at least 1.6 s. Then "Başlamak için dokun" pulses; the tap (a `click`, since a touch `pointerdown` doesn't count as a user gesture for sound or full screen) unlocks sound, goes full screen on phones and opens the menu with an entrance animation. The menu's background is `img/menu-bg.webp`.
- **`main.js`**: menu (animal picker with the animal's blue-paw ability under the preview, map chips: Orman / Karlı Dağ / Çöl / Karışık, "Arkadaşla Oyna", "📲 Telefona Yükle": uses `beforeinstallprompt` when the browser offers it, otherwise a guide for iPhone Safari, Samsung Internet, Android Chrome, in-app browsers and desktop; hidden when already installed), online screens (name, Oda Kur, code + Katıl, lobby with cards, map chips, bots chip, BAŞLAT), HUD (place, progress heads, item button roulette, banners, countdown), results, pause, help, input (left 62% of the screen or the jump button = jump, hold for higher; EĞİL button held = duck; 🐾 button = blue paw; item button; keyboard Space/↑/W, ↓/S, Q/Shift, E/Enter), fullscreen + landscape lock on phones, rotate hint, save (animal, map, toggles, races/wins) in `localStorage` key `man-run`. The loop splits each frame into equal sub-steps of at most `STEP` (no judder on any refresh rate); big hits freeze the sim for 50–80 ms (hit-stop). `?map=snow` forces a map.
